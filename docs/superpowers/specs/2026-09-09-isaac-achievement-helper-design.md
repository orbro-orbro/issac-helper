# 《以撒的结合》本地成就辅助系统设计

日期：2026-09-09  
状态：已确认设计，待用户审阅书面规格

## 1. 产品定义

本项目是一个在本机浏览器中运行的《以撒的结合：重生 / 忏悔+》成就辅助系统。它读取本机 Steam 与游戏存档中的进度，将结果转换为项目内的 JSON 快照，并围绕“接下来用哪个角色完成什么目标”组织界面。

系统不需要安装、打包、云服务或数据库。用户运行 `start.ps1` 后，本地服务监听 `127.0.0.1` 并自动打开浏览器。关闭启动终端即可停止服务。

### 核心目标

1. 按解锁方式组织全部成就，角色是最重要的主分类。
2. 首页用角色墙呈现整体进度，并优先暴露未完成目标。
3. 点击角色后，显示与该角色相关的全部成就，清楚区分已解锁和未解锁。
4. 用户可以在网页中选择 Steam 账户与存档槽，并主动更新项目内的进度快照。
5. 为未来的“一局多解”和下一局路线规划保留清晰的数据结构。

### 明确不做

- 不修改、恢复、删除或修复 Steam/游戏存档。
- 不做云同步、登录系统或远程访问。
- 不做 Electron、桌面安装包或游戏内覆盖层。
- 不在每次进度更新时重新抓取 Wiki。
- 第一版不实现复杂的自动路线求解器；只保留一个可解释的简单建议入口。

## 2. 使用流程

### 首次使用

1. 用户运行 `start.ps1`。
2. 脚本检查 Python 是否可用，启动仅绑定到 `127.0.0.1` 的本地服务。
3. 浏览器自动打开首页。
4. 如果项目内还没有有效快照，首页引导用户点击“更新数据”。
5. 用户选择检测到的 Steam 账户和存档槽。
6. 系统只读解析本地数据，校验成功后生成 JSON 快照。
7. 页面显示角色墙、分类入口和本次读取摘要。

### 日常使用

1. 用户打开首页，先看到上一次有效快照。
2. 需要同步时点击右上角“更新数据”。
3. 更新成功后，页面显示新增成就、角色进度变化和 Steam/Secrets 差异。
4. 用户从角色墙、分类或全部成就页进入具体目标。

## 3. 信息架构

### 顶层导航

- **角色**：默认首页，展示全部普通与里角色。
- **分类**：按解锁方式浏览非角色中心的成就。
- **全部成就**：搜索、排序和组合筛选完整目录。
- **更新数据**：右上角操作，不占用独立的永久导航项。

### 主分类：解锁方式

成就可以同时属于多个分类，不使用互斥文件夹模型。

1. **角色**：要求使用特定角色、解锁角色或影响角色初始状态的成就。
2. **挑战**：编号挑战的开放条件、完成目标和奖励。
3. **流程与 Boss**：章节、路线、结局、Boss 击杀和路径开放。
4. **收集与累计**：图鉴、捐款、击杀次数、拾取次数等长期进度。
5. **单局特殊**：连胜、限时、无伤、特殊组合或隐藏行为。
6. **每日与联机**：每日挑战、周期性目标和忏悔+在线成就。
7. **综合里程碑**：白金之神、死神等总体完成目标。

### 辅助标签

- DLC/版本
- 奖励类型
- 角色关系类型
- Boss/路线
- 普通或困难模式
- 已解锁、未解锁或同步异常

角色关系必须区分：

- `required_character`：必须使用该角色完成。
- `unlocks_character`：该成就会解锁角色。
- `starting_item_for_character`：改变角色初始物品。
- `related_character`：其他明确关系，不因名称中偶然出现角色名而自动归类。

## 4. 页面设计

### 4.1 首页：简明角色墙

首页只回答“今天打谁”。布局从上到下为：

1. 顶栏：产品名、角色/分类/全部成就导航、当前档位与更新时间、更新按钮。
2. 标题与总进度：`243 / 641` 形式的简明状态。
3. 一条下一局建议：只展示一个优先目标和“查看路线”入口。
4. 角色网格：角色头像、名称、相关成就完成数、未完成数和细进度条。
5. 其他解锁方式：以轻量文字按钮进入各分类。

默认按未完成目标的优先级排序，同时允许切换为游戏原始角色顺序。

### 4.2 角色详情页

角色详情页分三层：

1. **角色摘要**：角色名称、总完成数、是否已解锁里角色。
2. **通关便签与下一目标**：显示各通关标记及一个推荐目标。
3. **相关成就列表**：默认未解锁优先，显示中文名、英文名、ID、条件、奖励和标签；已解锁项降低视觉权重但不隐藏。

角色详情必须能筛选：

- 未解锁、全部、已解锁
- 通关标记、角色解锁、初始物品、困难模式里程碑
- DLC/版本

困难模式标记只有在存档中的完成标记被可靠解析后才显示红色困难状态；不能仅根据 Steam 成就猜测具体难度。

### 4.3 分类页

分类页复用统一的成就列表组件。页面顶部解释该分类的范围，并提供与分类相关的筛选项。例如：

- 挑战页按挑战编号、状态和奖励排序。
- 流程与 Boss 页按路线和 Boss 分组。
- 收集与累计页显示可读取的当前计数；无法从存档可靠读取的计数明确标为“暂无本地进度”。
- 每日与联机页单独提示需要在线服务或日期条件的目标。

### 4.4 全部成就页

提供中文/英文名称和数字 ID 搜索，支持组合标签。默认不一次铺开复杂筛选器；高级筛选通过一个可展开区域显示。

### 4.5 更新界面

点击顶栏“更新数据”后打开紧凑弹窗，而不是跳转到复杂仪表盘。弹窗内容为：

1. 自动检测到的 Steam 账户。
2. 存档槽 1、2、3，显示存在状态和文件时间。
3. 将读取的三类来源：Steam 成就缓存、Repentance+ 存档、Steam Schema。
4. “读取并更新”按钮。
5. 成功后的简短差异摘要，或失败后的明确原因。

## 5. 视觉系统

视觉目标是“安静的黑色工具界面”，而不是高装饰性的游戏主题皮肤。

### 色彩

- 背景黑：`#090909`
- 表面黑：`#121212`
- 抬升层：`#181716`
- 分隔线：`#292725`
- 骨白正文：`#E8E3D9`
- 灰褐辅助文字：`#89837A`
- 干血红强调：`#B54138`
- 灵魂蓝状态：`#6F929C`

### 字体

- 产品名与少量大标题：`KaiTi` / `STKaiti`，用于保留手写气质。
- 正文与控件：`Microsoft YaHei` / `Noto Sans SC`。
- ID、时间和比例：`Consolas` / 等宽字体。

### 标志性元素

手绘感只用于通关标记与关键目标符号。其他区域使用平直边框、充足留白和明确排版。界面不使用大面积纹理、不规则裁切、霓虹光效或大量渐变。

### 可用性

- 桌面端优先，同时支持窄屏浏览。
- 所有交互支持键盘焦点。
- 不只依赖颜色表达解锁状态，必须同时有图标或文字。
- 尊重 `prefers-reduced-motion`。
- 已解锁项降低权重但保持足够对比度。

## 7. 本地接口

本地服务只提供项目需要的最小接口：

- `GET /api/accounts`：返回检测到的 Steam 账户与可用存档槽。
- `GET /api/state?account=<id>&slot=<n>`：返回当前有效快照和目录版本。
- `POST /api/update`：接收账户 ID 和槽位，执行只读解析与快照更新。
- `GET /api/catalog`：返回本地版本化成就目录。

`POST /api/update` 不接受任意文件路径。账户必须来自已扫描的 Steam `userdata`，槽位只能是 1、2、3，AppID 固定为 `250900`。

## 8. 数据模型

### 成就目录记录

```json
{
  "id": 440,
  "name_en": "Meat Cleaver",
  "name_zh": "切肉刀",
  "steam_description": "Complete the Corpse with Isaac.",
  "unlock_condition_zh": "使用以撒击败母亲。",
  "reward": {
    "type": "collectible",
    "name_zh": "切肉刀"
  },
  "categories": ["character", "route_boss"],
  "character_relations": [
    {"character_id": "isaac", "type": "required_character"}
  ],
  "bosses": ["mother"],
  "dlc": "repentance",
  "sources": []
}
```

每条外部知识都在 `sources` 中保存来源 URL、页面标题、检索日期和适用版本。Steam 本地 Schema 字段和社区补充字段必须分开保存，不互相覆盖来源身份。

### 进度快照

```json
{
  "schema_version": 1,
  "steam_account_id": "<steam-account-id>",
  "slot": 1,
  "generated_at": "2026-09-09T00:00:00+08:00",
  "source_files": [],
  "steam_achievements": {},
  "game_secrets": {},
  "completion_marks": {},
  "summary": {},
  "sync_differences": []
}
```

`source_files` 记录路径、最后修改时间、大小和 SHA-256，便于判断快照是否来自最新文件。JSON 中不保存 Steam 登录凭据或其他账户秘密。

`data/profiles` 属于本机个人数据，项目将来初始化 Git 时默认加入 `.gitignore`。仓库中只保留不含真实账户信息的测试夹具和示例快照。

## 9. 数据读取与更新

### 路径发现

1. 从已知 Steam 根目录开始扫描 `userdata/*/250900`。
2. 读取游戏目录中的 `savedatapath.txt`，不要硬编码文档目录。
3. 列出实际存在的 `rep+persistentgamedataN.dat` 文件及时间。
4. 当前机器的已知路径作为快速路径，但每次仍验证文件存在性。

### Steam 成就

1. 按已验证的 Valve Binary KeyValues 规则解析 `UserGameStatsSchema_250900.bin`。
2. 按组读取用户缓存中的 `data` 位图。
3. 将有符号 32 位值按无符号位图处理。
4. 使用 `AchievementTimes` 解析 Unix 解锁时间。
5. 通过 Schema 的组与位索引映射数字成就 ID。

### 游戏 Secrets 与完成标记

1. 验证存档头和版本。
2. 对已确认的 `ISAACNGSAVE09R` 格式，在偏移 24 读取数量、从偏移 32 读取 Secret 字节。
3. 完成标记必须由独立的、带版本检测的解析逻辑读取；如果当前格式尚未被验证，只返回 Secrets，不推测困难标记。
4. 未识别的版本返回“格式暂不支持”，不尝试猜测偏移。

### 合并和校验

1. Steam Schema 形成当前官方目录骨架。
2. 本地静态目录补充中文名、条件、奖励和分类。
3. Steam 缓存与游戏 Secrets 分别保存状态，再生成差异列表。
4. 当前目录以 641 个成就为预期，但不永久硬编码总数；Schema 数量变化时给出版本提醒。
5. 只有在结构、ID 唯一性和必要字段全部校验通过后才写入快照。
6. 先写临时文件，再使用同目录原子替换更新 `current.json`。
7. 更新后生成与上一份快照的差异；没有变化时明确显示“进度未变化”。

## 10. 信源策略

信源优先级如下：

1. 本地存档和 Steam 缓存决定用户实际状态与时间。
2. 本地 Steam Schema 决定 ID 和 Steam 元数据。
3. Steam 官方页面/API 用于验证完整列表和版本。
4. wiki.gg 用于核对完整解锁条件和版本差异。
5. 灰机 Wiki 用于中文名称、中文说明和中文攻略表达。

发生冲突时保留双方来源并显示版本差异，不能静默覆盖。用户日常更新进度时不联网；成就目录的信源更新是单独的维护操作。

## 11. 错误处理与安全

### 安全边界

- 服务仅绑定 `127.0.0.1`。
- 更新接口只读取经过扫描和验证的 Steam/游戏目录。
- 不提供通用文件读取接口。
- 不执行来自目录 JSON、Wiki 内容或浏览器参数中的命令。
- 只在项目的 `data/profiles` 下写入生成文件。
- 不覆盖最近一份有效快照，除非新快照完成校验。

### 用户可见错误

- **未找到 Steam**：显示已检查的根目录和重新扫描入口。
- **未找到 AppID 250900**：说明该账户没有本地以撒数据。
- **未找到档位**：禁用该槽位，不产生空快照。
- **文件被占用或读取失败**：显示具体文件，建议退出游戏后重试。
- **存档格式不支持**：仍可使用 Steam 成就缓存，同时明确说明 Secrets/完成标记未更新。
- **Schema 与目录数量不同**：保留状态读取，标记成就目录需要更新。
- **Steam 与 Secrets 不一致**：作为同步差异展示，不视为解析失败。

## 12. 测试与验收

使用 Python 标准库 `unittest`，避免为了测试引入运行时依赖。

### 单元测试

- Binary KeyValues 的类型读取、递归对象和结束标记。
- 有符号 `int32` 到无符号位图的转换。
- 跨多个 32 位组的成就位索引与时间戳。
- `ISAACNGSAVE09R` 头、数量和 Secret 字节范围。
- 损坏、截断或未知版本文件的拒绝路径。
- 成就 ID 唯一性、分类枚举和信源字段。
- 角色关系类型和多标签查询。

### 集成测试

- 使用脱敏的最小二进制夹具完成一次端到端更新。
- 验证失败时旧 `current.json` 保持不变。
- 验证成功时历史差异与当前快照一致。
- 验证接口拒绝任意路径、未知账户和非法槽位。

### 本机验收基线

本机实测数字只记录在不提交的本地配置中，不能作为代码常量或上传到公开仓库。源文件更新后，测试应验证结构和计算逻辑，不要求个人进度数字保持不变。

### 界面验收

- 首页无需滚动即可看到标题、下一局建议和首批角色。
- 已解锁/未解锁在灰度显示下仍能区分。
- 键盘可完成导航、筛选、打开角色和更新数据。
- 窄屏下角色网格降为两列，导航不横向溢出。
- 更新失败后仍能浏览上一份快照。

## 13. 后续扩展

第一版稳定后再加入：

1. 一局多解规划：找出同角色、同难度、同兼容路线的目标组合。
2. 前置依赖图：解释为什么目标暂时不可完成。
3. 历史趋势：从本地快照计算进度变化，不上传数据。
4. 更精细的目标优先级：结合路线互斥、难度和用户钉选目标。

规划器的每条建议必须能解释其依据，不能只输出不可验证的“智能推荐”。
